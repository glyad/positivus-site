# Positivus Blog v1.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and release a bilingual, CMS-agnostic, multi-author Positivus Blog with static localized pages, two search experiences, governed discovery, accessible Editorial Grid layouts, and an honest UI-only comment prototype.

**Architecture:** A provider-neutral local JSON adapter supplies representative CMS records to a validated build-time model. Focused Node modules render localized static pages, search indexes, feeds, sitemaps, and redirects into `dist/`; dependency-free browser modules progressively enhance global search, blog filtering, article tools, and prototype comments. English routes live under `/blog/`, Hebrew peers under `/he/blog/`, and both reuse the existing shared design tokens, assets, language preference, build, test, packaging, and GitHub release flow.

**Tech Stack:** Node.js 20+, npm 10+, static HTML, CSS-compatible SCSS, vanilla JavaScript ES modules, JSON content fixtures, Node's built-in test runner, GitHub Actions, local Space Grotesk and existing Positivus assets.

## Global Constraints

- Treat `sources/` as authored source; never edit or commit `dist/`, `artifacts/`, or `coverage/`.
- Add no frontend or runtime dependency. Existing approved local icon assets are the only dependency exception.
- Preserve English LTR and Hebrew RTL capability together across every public blog page and viewport.
- Use `#B9FF66`, `#191A23`, `#F3F3F3`, black, white, Space Grotesk, 45px editorial-card radii, and the existing hard card shadow.
- Keep article body text at 16–18px, approximately 1.6 line height, and near a 70-character maximum measure.
- Every published article has exactly one primary category and no more than five governed tags.
- Browse and search pages use 12-item accessible numbered pagination; do not implement infinite scroll.
- English default routes use `/blog/...`; Hebrew routes use `/he/blog/...`; every translated record exposes reciprocal peer URLs and `hreflang` metadata.
- Global search indexes site pages, services, case studies, authors, and articles. Blog search indexes articles only.
- Only valid published content enters public pages, search indexes, feeds, sitemaps, and metadata.
- Prototype comment text stays in page memory only; never send it, log it, store it, or place it in a URL.
- Comment moderation, reporting, spam controls, editing, deletion, replies, reactions, privacy workflows, and comment-specific localization are not part of v1.2.0.
- Keep newsletter, consultation, authentication, and comment behavior explicitly labelled when it is simulated.
- Use regular two-parent GitHub merges; never squash or rebase. Never delete `develop`.

```js
// scripts/blog/local-json-adapter.mjs
import { readdir, readFile } from "node:fs/promises";
import { resolve } from "node:path";

const readJson = async (path) => JSON.parse(await readFile(path, "utf8"));

export async function loadLocalBlogSource({ sourceDir }) {
  const blogDir = resolve(sourceDir, "content", "blog");
  const articleDir = resolve(blogDir, "articles");
  const articleNames = (await readdir(articleDir)).filter((name) => name.endsWith(".json")).sort();
  return {
    settings: await readJson(resolve(blogDir, "settings.json")),
    categories: await readJson(resolve(blogDir, "categories.json")),
    tags: await readJson(resolve(blogDir, "tags.json")),
    authors: await readJson(resolve(blogDir, "authors.json")),
    series: await readJson(resolve(blogDir, "series.json")),
    articles: await Promise.all(articleNames.map((name) => readJson(resolve(articleDir, name))))
  };
}
```
